## Agent 协作的主要模式

### 1. 编排者-执行者模式（Orchestrator-Worker）

一个主 Agent 负责拆解任务、分配给子 Agent 执行，再汇总结果。

```
用户请求 → 编排者 Agent
              ├── 子 Agent A（搜索）
              ├── 子 Agent B（代码执行）
              └── 子 Agent C（写作）
                        ↓
                   汇总输出
```

### 2. 流水线模式（Pipeline）

Agent 串行处理，每个输出是下一个的输入。

```
数据采集 Agent → 清洗 Agent → 分析 Agent → 报告 Agent
```

### 3. 专家团队模式（Multi-Agent Debate）

多个专业 Agent 并行工作，通过讨论或投票得出最终答案，适合复杂决策。

## 关键技术要素

| 要素 | 说明 |
|------|------|
| **通信协议** | MCP（Model Context Protocol）、函数调用、消息队列 |
| **状态共享** | 共享内存、数据库、向量存储 |
| **任务分解** | 将复杂任务拆解为可独立执行的子任务 |
| **结果聚合** | 合并多个 Agent 的输出，处理冲突 |
| **错误处理** | 超时重试、降级策略、人工介入 |

## 主流框架对比

- **LangGraph** — 基于图结构，适合复杂状态流转
- **AutoGen（微软）** — 多 Agent 对话框架，易于上手
- **CrewAI** — 角色定义清晰，适合团队协作场景
- **Claude + MCP** — 通过 MCP 协议连接工具和外部服务

---

## 实践建议

1. **明确边界**：每个 Agent 职责单一，避免功能重叠
2. **上下文管理**：注意 token 消耗，只传递必要的上下文
3. **可观测性**：记录每个 Agent 的输入输出，便于调试
4. **人工审核节点**：关键决策处加入 Human-in-the-loop
5. **幂等设计**：Agent 任务失败可以安全重试
