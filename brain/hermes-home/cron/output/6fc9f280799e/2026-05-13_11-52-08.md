## Phase 2: 确认结果

检查脚本输出和退出码：
- 退出码 `0` + `"status": "completed|idle|stage_b_running|..."` → 任务完成，无需干预
- 退出码 `2` + `"status": "stuck"` → 有 pipeline 疑似卡死，进入 Phase 3 干预（最常见）
- 退出码 `2` + `"status": "uncertain"` → 信号矛盾，进入 Phase 3 人工推理
- 退出码 `1` → 脚本错误，检查 TG token、wiki 路径、brain repo 权限

> **注意**：`stuck` 和 `uncertain` 都 exit(2) 且都需要进入 Phase 3。区别在于 `stuck` 是明确的超时判断（已用 > 阈值），`uncertain` 是信号矛盾（如 stage_c 显示完成但内容为空）。两者处理方式相同：看 `should_intervene` 字段决定是否执行干预操作。

## Pitfalls

### 0. git ls-files 俄文/中文文件名导致 FileNotFoundError
当 wiki/sources 目录下的文件名包含非 ASCII 字符（如中文）时，`git ls-files` 默认会为这些文件添加引号和转义，导致 Python `Path / filename` 拼接出错（FileNotFoundError）。修复方法：`git ls-files` 加 `-z` 参数（NUL 分隔），然后用 `\0` split 代替 `splitlines()`。

### 1. uncertain 频繁出现
说明 wiki 文件系统状态不一致（如手动操作遗留文件）。用 `git -C $WIKI_PATH status` 查看脏文件并清理。

### 2. TG 未发送（tg_sent: false）
检查 `~/.agent-brain-plugins.env` 里 `YOUTUBE_WIKI_TG_TOKEN` 是否有效：
`curl -s "https://api.telegram.org/bot${YOUTUBE_WIKI_TG_TOKEN}/getMe"`

### 3. brain push 失败
检查 `~/agent-brain-plugins` 的 git remote 和 token：
`git -C ~/agent-brain-plugins remote -v`

### 4. 废弃 pipeline（video link 已被删除）
当 `raw/youtube-links/<video_id>.md` 文件已被删除（如 `chore: clean slate` 清理提交），该视频的 pipeline 无法继续。
此时 agent 应直接创建 stage-b / stage-c / stage-d done 的 empty commits 来关闭这些废弃 pipeline，而非尝试重新触发 webhook：
```bash
git commit --allow-empty -m "chore: stage-b done [pipe:<pipeline_id>] [run:watchdog-cleanup-$(date +%s)]"
git commit --allow-empty -m "chore: stage-c done [pipe:<pipeline_id>] [run:watchdog-cleanup-$(date +%s)]"
git commit --allow-empty -m "chore: stage-d done [pipe:<pipeline_id>] [run:watchdog-cleanup-$(date +%s)]"
git push origin main
```
判断依据：`git log --all -- "raw/youtube-links/<video_id>.md"` 显示该文件被删除且无重新创建。

### 5. Stage C 构建器跳过已有 Source 页面
`sop_wiki_builder_v3.py` 检查 `wiki/sources/<stem>.md` 是否存在，若存在则跳过该分析报告。
如果一个 pipeline 的 Stage B 完成但 Source 页面已在之前 pipeline 运行中创建（不同 run_id），则 builder 退出 "所有报告均已处理，无新内容。"，但不会创建 `stage-c done` commit，导致 pipeline 卡住。
**解决方法**：agent 需手动创建 `stage-c done` commit，或者检查是否需要补充实体/概念页面后再提交。

### 6. 脚本 off-by-one 缺陷（current_stage 偏移 1）
脚本 `judge_pipeline` 中 `STEP_NAMES = {1: "stage_b", 2: "stage_c", 3: "stage_d", 4: "completed"}`。
旧版使用 `STEP_NAMES.get(max_step + 1)` 导致：
- queue 后显示 stage_c 实际应为 stage_b
- stage-b done 后显示 stage_d 实际应为 stage_c
2026-05-13 巡航 #134 时已修复为 `STEP_NAMES.get(max_step)`。如果发现阶段名称偏移 1，检查脚本中这行是否正确。
