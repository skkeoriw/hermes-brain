## Phase 2: 判断 pipeline 健康度（Agent 推理）

综合以下信息做出判断，**不要写死阈值，要结合上下文推理**：

**需要读取的数据：**
- `pipeline-context.json`：各 stage 的 start_time、end_time、status
- 最新 run-log 的时间戳和内容
- wiki/ 实际文件数（与 pipeline-context 记录对比）
- `watchdog-state.json`：历史干预记录
- 当前 UTC 时间

**判断维度：**
1. **无活跃 pipeline**：youtube-links 没有新文件，或 pipeline-context 为空 `{}` → `idle`
2. **Stage B 运行中**：youtube-links 有新文件，但无对应分析文件，run-log 有 stage_b 且无 end_time → `stage_b_running`
3. **Stage B 可能卡死**：youtube-links 有新文件超过 15 分钟，但仍无分析文件 → `stage_b_stuck`
4. **Stage C 等待触发**：有分析文件，pipeline-context 有 stage_b 完成，但无 stage_c → `stage_c_waiting`（正常过渡，< 5 分钟可接受）
5. **Stage C 运行中**：pipeline-context 有 stage_c 但无 end_time，或有 run-log 显示 stage_c 在运行 → `stage_c_running`
6. **Stage C 可能卡死**：stage_c 开始超过 30 分钟，wiki/ 文件数与预期相差悬殊 → `stage_c_stuck`
7. **Stage D 等待触发**：stage_c 完成但无 Stage D run-log，< 10 分钟可接受 → `stage_d_waiting`
8. **Stage D 可能卡死**：stage_c 完成超过 15 分钟，仍无 TG 通知 run-log → `stage_d_stuck`
9. **全链路完成**：pipeline-runs/ 有归档文件，tg_sent: True → `completed`

**更新 watchdog-state.json：**
```bash
python3 << 'PYEOF'
import json, os, datetime

state_file = os.path.join(os.environ.get('WIKI_PATH', ''), 'logs/watchdog-state.json')
run_id = "当前 run_id"
stage = "stage_c"

state = {}
try:
    state = json.loads(open(state_file).read())
except:
    pass

state.setdefault('runs', {}).setdefault(run_id, {}).setdefault(stage, {'count': 0, 'history': []})
state['runs'][run_id][stage]['count'] += 1
state['runs'][run_id][stage]['history'].append({
    'at': datetime.datetime.utcnow().strftime('%Y-%m-%dT%H:%M:%SZ'),
    'action': '描述干预动作',
    'result': '成功/失败'
})

with open(state_file, 'w') as f:
    json.dump(state, f, ensure_ascii=False, indent=2)
PYEOF
```
