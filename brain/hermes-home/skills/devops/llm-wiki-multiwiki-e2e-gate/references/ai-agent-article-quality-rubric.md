# AI Agent Wiki 文章质量验收 Rubric（中文）

适用场景：重建或增量扩写 `raw/articles/*.md`，并要求后续图谱编译质量稳定。

## 硬性门槛（Fail-fast）
1. 篇幅：每篇 >= 500 中文字（建议 800+）。
2. 结构：必须含 4 段标题（可同义替换但语义必须完整）：
   - 问题定义
   - 方法与架构
   - 失败案例/反例
   - 落地清单与反思
3. 去模板化：任意两篇若大段同构复述，判为不合格（需要重写而非微调）。
4. 可执行性：至少 3 条可执行建议（步骤、阈值、指标、角色分工之一）。

## 深度门槛（精品标准）
1. 观点密度：不是“工具介绍”，而是“方法论 + 边界条件 + 取舍”。
2. 工程真实性：包含失败模式、触发条件、监控信号、补救路径。
3. 决策透明：说明“为何选A不选B”，给出反例或失效边界。
4. 组织可复用：结论可转成 SOP、评审清单或 CI 规则。

## 图谱联动门槛
1. 新增 raw 后，`wiki/entities|concepts|comparisons` 应有实质增量或修订。
2. Telegram/报告需给出量化变化：
   - 新增/更新实体数 + 名称
   - 关系变化（按类型）+ 示例边
   - 受影响概念页列表
3. 若 raw 改变但图谱近空或无实质变化，标记 `quality-failed`，不可报“成功构建”。

## 运行后验收输出（建议格式）
- 二元结论：通过/不通过
- 失败项清单：按硬性门槛优先
- 修复建议：逐条映射到文件路径
- 本次增量证据：run_id / commit / changed files / no_raw_change gate 结果
